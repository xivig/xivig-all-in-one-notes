1. ELOQUENT ORM ARCHITECTURE & MODERN BEST PRACTICES
================================================================================
In Laravel 11/12/13:
- Always define foreign keys with cascade constraints in migration files.
- Enable Eloquent Strict Mode during local development to catch lazy loading and unfillable attributes early:

In `app/Providers/AppServiceProvider.php`:
```php
use Illuminate\Database\Eloquent\Model;

public function boot(): void
{
    // Throws exceptions when lazy loading relationships in non-production environments
    Model::preventLazyLoading(!app()->isProduction());
    
    // Prevent silently discarding unfillable attributes
    Model::preventSilentlyDiscardingAttributes(!app()->isProduction());
}
```

2. ONE-TO-ONE RELATIONSHIPS (hasOne & belongsTo)
================================================================================
Example: A `User` has one `Profile`.

1. Migration Schema:
```php
// create_profiles_table
Schema::create('profiles', function (Blueprint $table) {
    $table->id();
    $table->foreignId('user_id')->constrained()->cascadeOnDelete();
    $table->string('bio', 500)->nullable();
    $table->string('avatar_path')->nullable();
    $table->string('phone', 30)->nullable();
    $table->timestamps();
});
```

2. User Model (`app/Models/User.php`):
```php
use Illuminate\Database\Eloquent\Relations\HasOne;

public function profile(): HasOne
{
    return $this->hasOne(Profile::class);
}
```

3. Profile Model (`app/Models/Profile.php`):
```php
use Illuminate\Database\Eloquent\Relations\BelongsTo;

public function user(): BelongsTo
{
    return $this->belongsTo(User::class);
}
```

4. Usage:
```php
// Create with relationship
$user = User::find(1);
$user->profile()->create([
    'bio' => 'Senior Laravel Developer',
    'phone' => '+1 555-0199',
]);

// Access related profile
$bio = $user->profile?->bio;
```

3. ONE-TO-MANY RELATIONSHIPS (hasMany & belongsTo)
================================================================================
Example: An `Author` has many `Posts`.

1. Migration Schema:
```php
// create_posts_table
Schema::create('posts', function (Blueprint $table) {
    $table->id();
    $table->foreignId('user_id')->constrained()->cascadeOnDelete();
    $table->string('title');
    $table->string('slug')->unique();
    $table->text('content');
    $table->boolean('is_published')->default(false);
    $table->timestamps();
});
```

2. User Model:
```php
use Illuminate\Database\Eloquent\Relations\HasMany;

public function posts(): HasMany
{
    return $this->hasMany(Post::class)->latest();
}

public function publishedPosts(): HasMany
{
    return $this->hasMany(Post::class)->where('is_published', true)->latest();
}
```

3. Post Model:
```php
use Illuminate\Database\Eloquent\Relations\BelongsTo;

public function author(): BelongsTo
{
    return $this->belongsTo(User::class, 'user_id');
}
```

4. MANY-TO-MANY RELATIONSHIPS (belongsToMany & PIVOT ATTRIBUTES)
================================================================================
Example: `Users` and `Roles` connected via a `role_user` pivot table with metadata.

1. Pivot Migration:
```php
Schema::create('role_user', function (Blueprint $table) {
    $table->id();
    $table->foreignId('user_id')->constrained()->cascadeOnDelete();
    $table->foreignId('role_id')->constrained()->cascadeOnDelete();
    $table->string('assigned_by')->nullable();
    $table->timestamp('expires_at')->nullable();
    $table->timestamps();
    
    // Prevent duplicate role assignments
    $table->unique(['user_id', 'role_id']);
});
```

2. User Model:
```php
use Illuminate\Database\Eloquent\Relations\BelongsToMany;

public function roles(): BelongsToMany
{
    return $this->belongsToMany(Role::class)
        ->withPivot('assigned_by', 'expires_at')
        ->withTimestamps();
}
```

3. Role Model:
```php
use Illuminate\Database\Eloquent\Relations\BelongsToMany;

public function users(): BelongsToMany
{
    return $this->belongsToMany(User::class)
        ->withPivot('assigned_by', 'expires_at')
        ->withTimestamps();
}
```

4. Practical Operations:
```php
$user = User::find(1);

// Attach a role with pivot data
$user->roles()->attach($roleId, [
    'assigned_by' => 'SuperAdmin',
    'expires_at' => now()->addYear(),
]);

// Sync roles (removes unlisted roles, adds new ones)
$user->roles()->sync([1, 2, 3]);

// Toggle role
$user->roles()->toggle($roleId);

// Access pivot data
foreach ($user->roles as $role) {
    echo $role->name . ' - assigned by: ' . $role->pivot->assigned_by;
}
```

5. HAS-MANY-THROUGH & HAS-ONE-THROUGH RELATIONSHIPS
================================================================================
Example: A `Country` has many `Posts` through `Users`.

```
[Country] 1 ---- * [User] 1 ---- * [Post]
```

In `Country` model:
```php
use Illuminate\Database\Eloquent\Relations\HasManyThrough;

public function posts(): HasManyThrough
{
    return $this->hasManyThrough(
        Post::class,       // Target final model
        User::class,       // Intermediate bridge model
        'country_id',      // Foreign key on users table...
        'user_id',         // Foreign key on posts table...
        'id',              // Local key on countries table...
        'id'               // Local key on users table...
    );
}
```

6. POLYMORPHIC RELATIONSHIPS (ONE-TO-MANY COMMENTS)
================================================================================
A single `comments` table can store comments for `Post`, `Video`, or `Product` models.

1. Polymorphic Migration Schema:
```php
Schema::create('comments', function (Blueprint $table) {
    $table->id();
    $table->foreignId('user_id')->constrained()->cascadeOnDelete();
    $table->text('body');
    // Generates commentable_id (bigint) and commentable_type (string) with index:
    $table->morphs('commentable');
    $table->timestamps();
});
```

2. Comment Model:
```php
use Illuminate\Database\Eloquent\Relations\MorphTo;

public function commentable(): MorphTo
{
    return $this->morphTo();
}
```

3. Post & Video Models:
```php
use Illuminate\Database\Eloquent\Relations\MorphMany;

public function comments(): MorphMany
{
    return $this->morphMany(Comment::class, 'commentable')->latest();
}
```

4. Custom Morph Map in `AppServiceProvider.php` (Never store raw class strings in DB):
```php
use Illuminate\Database\Eloquent\Relations\Relation;

public function boot(): void
{
    Relation::morphMap([
        'post' => \App\Models\Post::class,
        'video' => \App\Models\Video::class,
        'product' => \App\Models\Product::class,
    ]);
}
```

7. POLYMORPHIC MANY-TO-MANY (UNIVERSAL TAGGING SYSTEM)
================================================================================
Example: `Post` and `Video` models can both have many `Tags`.

1. Migration:
```php
Schema::create('tags', function (Blueprint $table) {
    $table->id();
    $table->string('name')->unique();
    $table->string('slug')->unique();
    $table->timestamps();
});

Schema::create('taggables', function (Blueprint $table) {
    $table->id();
    $table->foreignId('tag_id')->constrained()->cascadeOnDelete();
    $table->morphs('taggable'); // taggable_id, taggable_type
});
```

2. Tag Model:
```php
use Illuminate\Database\Eloquent\Relations\MorphToMany;

public function posts(): MorphToMany
{
    return $this->morphedByMany(Post::class, 'taggable');
}

public function videos(): MorphToMany
{
    return $this->morphedByMany(Video::class, 'taggable');
}
```

3. Post Model:
```php
use Illuminate\Database\Eloquent\Relations\MorphToMany;

public function tags(): MorphToMany
{
    return $this->morphToMany(Tag::class, 'taggable');
}
```

8. ELIMINATING THE N+1 QUERY PROBLEM & EAGER LOADING
================================================================================
The N+1 problem occurs when a query executes 1 query for the parent records,
then N additional queries for each child record in a loop.

Bad (101 SQL queries for 100 posts):
```php
$posts = Post::all();
foreach ($posts as $post) {
    echo $post->author->name; // Executes a separate SELECT query per post!
}
```

Good (Only 2 SQL queries total with Eager Loading):
```php
$posts = Post::with(['author', 'tags'])->get();
foreach ($posts as $post) {
    echo $post->author->name; // Already in memory!
}
```

Constrained Eager Loading:
```php
$users = User::with(['posts' => function ($query) {
    $query->where('is_published', true)->orderBy('created_at', 'desc');
}])->get();
```

Counting Relationships without loading models (`withCount`):
```php
// Adds posts_count attribute to the User model using an efficient subquery
$users = User::withCount('posts')->get();
foreach ($users as $user) {
    echo "{$user->name} has written {$user->posts_count} posts.";
}
```

9. DATABASE TRANSACTIONS (TRANSACTIONAL SAFETY & DEADLOCK RETRIES)
================================================================================
Whenever you perform multiple database operations that must succeed or fail
as a single atomic unit, wrap them in a database transaction.

```php
use Illuminate\Support\Facades\DB;

// Automatic transaction with 5 automatic retries in case of database deadlocks
DB::transaction(function () use ($sender, $receiver, $amount) {
    // Pessimistic locking (lockForUpdate) prevents race conditions
    $fromAccount = Account::where('id', $sender->id)->lockForUpdate()->firstOrFail();
    $toAccount = Account::where('id', $receiver->id)->lockForUpdate()->firstOrFail();

    if ($fromAccount->balance < $amount) {
        throw new \Exception('Insufficient funds.');
    }

    $fromAccount->decrement('balance', $amount);
    $toAccount->increment('balance', $amount);

    TransactionRecord::create([
        'from_account_id' => $fromAccount->id,
        'to_account_id' => $toAccount->id,
        'amount' => $amount,
        'reference' => 'TXN-' . Str::uuid(),
    ]);
}, 5);
```

10. MODEL OBSERVERS & LIFECYCLE HOOKS
================================================================================
Observers extract business logic (like generating slugs or cleaning up files)
out of controllers and models.

Create Observer:
php artisan make:observer PostObserver --model=Post

In `app/Observers/PostObserver.php`:
```php
<?php

namespace App\Observers;

use App\Models\Post;
use Illuminate\Support\Str;

class PostObserver
{
    /**
     * Handle the Post "creating" event.
     */
    public function creating(Post $post): void
    {
        if (empty($post->slug)) {
            $post->slug = Str::slug($post->title) . '-' . Str::random(6);
        }
    }

    /**
     * Handle the Post "deleted" event (cleanup attached assets).
     */
    public function deleted(Post $post): void
    {
        // Delete associated featured image from storage
        if ($post->featured_image) {
            \Illuminate\Support\Facades\Storage::disk('public')->delete($post->featured_image);
        }
    }
}
```

In Laravel 11+, register observers using the `#[ObservedBy]` attribute directly on the model:
```php
namespace App\Models;

use App\Observers\PostObserver;
use Illuminate\Database\Eloquent\Attributes\ObservedBy;
use Illuminate\Database\Eloquent\Model;

#[ObservedBy([PostObserver::class])]
class Post extends Model
{
    // ...
}
```
